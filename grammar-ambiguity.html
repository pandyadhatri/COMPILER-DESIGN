One string,
two trees — or exactly one.

That single fact is the whole difference between an ambiguous and an unambiguous grammar. Below: the definitions, a repeatable conversion procedure, and ten worked examples.

Derivation 2

Both trees derive id + id * id from E → E+E | E*E | id — that duplication is what ambiguity means.
01 — Definitions

Ambiguous vs. non-ambiguous, precisely

Ambiguous grammar

A context-free grammar G is ambiguous if there exists at least one string in its language for which more than one parse tree exists — equivalently, more than one leftmost (or more than one rightmost) derivation.

∃ w ∈ L(G) : more than one parse tree for w

Non-ambiguous grammar

A grammar is unambiguous if every string in its language has exactly one parse tree — exactly one leftmost derivation and exactly one rightmost derivation. Structure, not just the string, is guaranteed unique.

∀ w ∈ L(G) : exactly one parse tree for w
02 — Procedure

Step-by-step: converting an ambiguous grammar to an unambiguous one

1

Find where the grammar branches two ways

Pick a string the grammar accepts and try to build it two different structural ways. If you succeed, you've located the ambiguity — usually a rule that lets an operator, or a construct like nested if-statements, be grouped more than one way.

E → E + E | E * E | id  →  id + id * id has two trees
2

Fix precedence between the competing rules

Decide, outside the grammar, which operator should bind tighter (e.g. * before +). This ordering becomes a hierarchy of non-terminals, one per precedence level, from loosest-binding at the top to tightest at the bottom.

precedence: * binds tighter than +
3

Fix associativity within each level

Decide whether repeated uses of the same operator group left-to-right or right-to-left. Left-associative operators get left-recursive rules; right-associative operators get right-recursive rules.

+ and * are left-associative → left-recursive rule
4

Introduce one non-terminal per precedence level

Create a chain of non-terminals — one level per precedence tier — where each level can only be built from the next tighter level, plus its own operator applied to itself.

E (level: +) → T (level: *) → F (level: atoms)
5

Rewrite each level as: itself-op-next | next

Every level's rule has exactly two productions: a left-recursive one that consumes its own operator, and a fallback that drops straight to the next tighter level. The bottom level handles atoms and parenthesised sub-expressions.

F → ( E ) | id
Before — ambiguous
E → E + E | E * E | id
→
After — unambiguous
E → E + T | T T → T * F | F F → ( E ) | id
6

Verify: rebuild the troublesome string

Re-derive the original test string against the new grammar. If only one parse tree comes out — and it matches the precedence and associativity you intended — the rewrite is correct.

id + id * id → now only: E → E+T, T → T*F (i.e. id + (id*id))
